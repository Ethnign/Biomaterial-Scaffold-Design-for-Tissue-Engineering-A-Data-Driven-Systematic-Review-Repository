# Repository reorganization notes (2026-09-29)

This reorganization followed the proposal in *"Reorganización del repositorio de biomateriales"* (uploaded 2026-09-29). This note records what was actually done against that proposal's own sequence (Section 4) and completion criteria (Section 6), including what is still open, per this project's standing rule of not minimizing or hiding gaps.

**Addendum (2026-09-30), after a second, stricter line-by-line audit against the original proposal:** two gaps were found that the first pass of this reorganization missed or under-disclosed.

1. **Fixed:** the proposal's Section 4, item 6 explicitly asks to cite the published version (`v1.0.0`) from the manuscript's Data Availability statement. The first pass created and pushed the `v1.0.0` tag but never added the citation to the manuscript text. `manuscript/Full_Draft_Paper_LaTeX_v3.tex`'s Data Availability paragraph now names `v1.0.0` explicitly as "the citable snapshot corresponding to this manuscript"; recompiled clean (0 errors, 15 pages).
2. **Not fixed, now explicitly disclosed:** the proposal's Section 2 explicitly asks to "centralizar las rutas de entrada y salida para evitar que el análisis dependa de una carpeta personal o de `/content/`" and, if Colab is used, to explain how the project is mounted/downloaded and where inputs live. `notebooks/pipeline_Q3_BioBERT_5ejes_CORREGIDO.ipynb` still hardcodes `/content/...` paths (Colab's local, ephemeral disk) throughout essentially every I/O cell (input PDFs, every intermediate CSV/NPY, the final `.gexf`/figure outputs) -- there is no single project-root variable, and no `drive.mount()`/download step is documented. The first pass of this reorganization extracted the notebook's *parameter dictionaries* into `config/*.json` but did not touch its *path* structure, and did not call this specific gap out by name -- it was folded into the more generic "`config/` is not read back by the notebook" note below, which understated it. This is now named explicitly because rewriting ~12 cells' worth of hardcoded paths in a 40-cell, GPU-dependent notebook that cannot be executed or tested in this environment (no GPU, no input PDFs) is a real risk of silently introducing a bug that would only surface on the next real Colab run. Recommended fix, to be done with the ability to actually re-run the notebook afterward to confirm nothing broke: add one `PROJECT_ROOT` (or `BASE_DIR`) cell near the top, defaulted to `/content` so behavior is unchanged in Colab, and replace every hardcoded `/content/...` literal with a path built from that variable.

## What is intentionally not done yet (and why)

The proposal itself says modularization does not need to precede reorganization ("No es necesario modularizar todo antes de reorganizar los archivos"). Consistent with that:

- **`src/` is empty.** The full pipeline still lives inline in the notebook. See `src/README.md`.
- **`config/*.json` is not read back by the notebook.** It is a faithful, reviewable extraction of the notebook's own dictionaries/thresholds, kept in sync by hand for now. See `config/README.md`.
- **The notebook's I/O paths are not centralized and still hardcode `/content/`** (see the 2026-09-30 addendum above for the full explanation and the recommended fix). This is a distinct, more concrete gap than the general "not modularized yet" point above -- it is explicitly requested in the proposal's Section 2 and was not caught until the second audit pass.
- **The fragment/topic/entity-level intermediate tables** proposed in the guide's Section 2 (`studies.csv`, `fragments.csv`, `topic_assignments.csv`, `axis_assignments.csv`, `entities.csv`, each with a `run_id`) do not exist as separate files. The closest existing artifact is `data/processed/clasificacion_5ejes_topicos.csv` (topic-level, not fragment-level). See `data/processed/README.md`.
- **`results/metrics/run_manifest.json`** is manually reconstructed from the notebook's own cells (seed, package list, recorded Python version), not emitted by an automated run-logging step. Package versions were never pinned for the run that produced the current results, which is disclosed rather than backfilled with invented version numbers.
- **No independent re-execution of the pipeline** was performed as part of this reorganization (see above).
- **Raw search exports and full-text PDFs remain unavailable** in the repository (licensing/size), as before this reorganization.
